# 拖拽嵌入改「简洁文档链接」：调研与实现方案（2026-10-25）

> 需求：现在拖文档进画布生成的是 600×420 的大嵌入框（iframe），观感偏重。想改成 Obsidian Excalidraw 那种**一行「名字 + 链接」的简洁文字**；要看详细内容时点它分屏打开（分屏点击查看已实现）。参考源码：`/Users/xieyue/Downloads/obsidian-excalidraw-plugin-2.29.0`。

---

## 一、调研结论

### 1. Obsidian 插件的「简洁名字+链接」是什么（读其源码与 Release-notes）

- 它的形态是**带链接的文本元素**：拖/贴一个内部链接进画布时，按「只显示文件名（别名）」生成文字（docs/Release-notes.md:3454），链接附在元素上；`CTRL/CMD+click`（或点文字中的链接）导航（:1398）。链接样式（主题链接色/下划线）由它**私有的 vendor fork**（`@zsviczian/excalidraw`，不在附件包里）渲染——上游没有这层样式。
- 它**另有一种**完整嵌入（`![[note]]` transclusion，iframe 大框，`customEmbeddableUtils.ts` 那套）——与我们现在的 iframe 框对应。即 Obsidian 本来就是**两形态并存**：紧凑链接文本 vs 完整嵌入大框。

### 2. 我们的 vendor 不需要 fork 就能做到（关键核实）

- 上游 0.18.1 文本元素原生支持 `link` 属性；**单击命中带链接元素即触发 `onLinkOpen`**（engine.js 已核对：pointerup → `hitLinkElement.link` → `this.props.onLinkOpen(...)`，未 preventDefault 才 window.open）。我们 StudioApp 的 onLinkOpen **已经拦截 `siyuan:` 前缀** → `openDocLink` → `siyuan:block/<id>` → 右侧分屏。**点击跳转链路零新代码**。
- 上游不给链接文字加色/下划线 → 创建时把元素 `strokeColor` 设为主题强调色（`--exs-accent` 两态：浅 `#6965db` / 深 `#a8a5ff`），观感即「链接色文字」；下划线不画（Obsidian 也是 fork 才有，省掉）。
- 文本元素构造：用 vendor 公开 API `convertToExcalidrawElements`（skeleton → 正规元素，自动补默认字段/尺寸），不手工拼字段——比 embeddable 的手工构造更稳。

### 3. 标题从哪来

拖入时批量查内核 SQL：`select id, content from blocks where id in (…)`——文档块的 `content` 就是标题，段落块取文本前 32 字截断。宿主侧已有 SQL 通道（refreshBoardLib 同款），加一个小通道给画布侧用，带会话级缓存。

## 二、方案（推荐 A：拖拽改紧凑链接文本，菜单保留完整嵌入）

**语义分工**（与 Obsidian 一致）：**拖 = 引用**（紧凑链接文本）；☰「嵌入思源块…」= **嵌入**（完整 iframe 大框）。存量画布里的旧大框不动、照常可用（⌘点击/右上按钮跳转都保留）。

1. **构造**（新纯函数，`embeddable.ts` 或独立小模块）：
   `makeBlockLinkTextElement({ id, text, blockId, x, y, accent, fontSize=20, seed, index })` →
   skeleton `{ type:"text", text, x, y, fontSize, fontFamily:手写体, strokeColor:accent, textAlign:"left", link:"siyuan:block/<id>" }` 经 `convertToExcalidrawElements` 转正规元素；标题截断 32 字（超出加 …）。
2. **拖入分支改造**（StudioApp `onCanvasDrop` 思源分支）：解析 ids → 调新宿主通道 `fetchBlockTitles(ids)`（失败回退「块 xxxxx」）→ 生成 text 元素，网格排布（估算宽 `min(32字宽, 420)`、行高 `fontSize×1.25 + 16`）→ updateScene + 选中。提示条文案改「松开以插入思源链接」。
3. **跳转**：单击链接文字 → vendor 原生 onLinkOpen → 既有 `siyuan:` 拦截 → `openBoardDocLink` → `openTab position:"right"` 分屏。不改一行。
4. **宿主通道**：`index.ts` 加 `fetchBlockTitles(ids): Promise<Record<string,string>>`（SQL in 子句、引号转义、Map 缓存），StudioTabHost 补该字段。

**备选 B（不推荐为默认）**：仍用 embeddable 元素、`renderPluginEmbeddable` 渲染成带底色圆角小卡片（图标+标题+↗，纯 DOM、无 iframe、无沙箱问题），点击走 React onClick → onOpenDocLink。观感更「卡片」，但元素更重（固定宽高、导出/搜索语义差）、不如 text 方案贴 Obsidian。若你觉得 A 的纯文字太素，可以 A 先上、B 做成设置项二选一。

## 三、工作量与验收

改动面：1 个纯函数 + 1 个宿主通道 + drop 分支改造 + 文案/测试。预计半天。

验收（补进 release-checklist 第 66 条）：拖单篇/多篇文档 → 画布出现**强调色标题文字**；单击任一条 → 文档右侧分屏打开；拖段落块 → 同款（文本截断 32 字）；拖笔记本 → 忽略提示不变；☰「嵌入思源块…」仍出完整大框；存量旧大框 ⌘点击跳转不受影响。测试：`makeBlockLinkTextElement` 形状/截断/链接形态、SQL in 拼接转义、drop 分支契约更新（interframe 测试同步）。
