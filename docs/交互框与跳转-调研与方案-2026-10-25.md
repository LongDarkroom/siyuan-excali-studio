# 文档↔白板双向交互框：调研与实现方案（2026-10-25）

> 需求（用户原话归纳）：
> **A. 拖拽嵌入**：把思源文档树里的文档直接拖进白板画布 → 自动生成可交互的嵌入框；点击框打开对应文档页签，与白板并排（双页阅读）。
> **B. 斜杠插入**：在思源文档里打斜杠菜单 →「插入白板」→ 出现白板交互框；点击跳转到白板（对标 `/Users/xieyue/Downloads/思源笔记/data/plugins/siyuan-embed-excalidraw` 的体验）。

> 本文 = 三路调研（参照插件逆向 / 思源源码拖拽协议 / 本插件现有资产盘点）+ 落地方案。不含实施。

## 一、调研结论

### 1.1 参照插件 siyuan-embed-excalidraw 的机制（逆向其 index.js / app/ / embed/）

它的「文档内嵌入可交互白板」其实是**三层拼装**，没有用任何非公开渲染接口：

| 层 | 做法 |
|---|---|
| 插入 | 斜杠菜单（`protyleSlash`，filter `excalidraw`）→ 生成占位 SVG 写入 `data/assets/` → `protyle.insert("![](assets/xxx.svg)")` —— **就是一条普通 markdown 图片块** |
| 展示 | 思源原生渲染该图片块（SVG 本身带内嵌场景，所见即所得）；再往块的 `.protyle-attr` 贴一个「Excalidraw」小徽标 |
| 跳转/编辑 | ① 块头悬停按钮：扫描编辑器 DOM，往图片块的 `.protyle-action` 区注入 ✏️ 图标，点击 → `openTab` custom 打开自家 `app/index.html` 编辑器页签；② `open-menu-image` 事件Bus（思源原生）：图片右键菜单加「编辑」项；③ 图片点击本身仍是思源的图片预览（**它也没有劫持单击**） |

**要点**：所谓「交互框」不是 iframe 也不是挂件块，就是**图片块 + 注入的悬停/右键入口**。这层认识直接决定功能 B 的形态——我们不需要发明新块类型。

### 1.2 思源文档树拖拽协议（读思源源码 Files.ts / gutter/index.ts / constants.ts）

| 拖拽源 | dataTransfer 内容 |
|---|---|
| 文档树（纯文档，支持多选） | `application/siyuan-documents` = `JSON.stringify({ids:[...]})` |
| 文档树（混选/含笔记本） | `application/siyuan-file` = 逗号拼接的 nodeId 或 path（path 形态 = 笔记本） |
| 正文块条（⋮ 拖拽） | 动态 MIME：`application/siyuan-gutter<type>\u200b<subtype>\u200b<ids>\u200b<workspaceDir>`，payload JSON 含 {html, notebookID, rootID}；**块 ids 藏在 MIME 第三段**（零宽空格分隔） |

- 文档树拖拽**不带 text/plain** ⇒ vendor 画布现有的 text/plain 播放器（拖 http 链接生成网页框）不会误触发，我们的监听与之零冲突。
- 注意这是思源内部协议（无兼容承诺），解析必须防御式：types 里没有就当没拖。

### 1.3 本插件现有资产（全部可复用，两个功能都是「接线」而非「造轮子」）

- **嵌入框链路**（刚修好的 P0）：`embedSiYuanBlock` → `makeEmbeddableElement` + `embedPageLink` → `renderPluginEmbeddable` 自渲染同源 iframe——功能 A 的画布侧已经存在，缺的只是「拖拽入口」。
- **嵌入渲染页**（src-embed/siyuan/index.html）：已有 hover「在思源中打开」按钮，但目前是 `href="siyuan://blocks/…" target=_top`——桌面端行为不可靠，需改成 postMessage。
- **⌘/Ctrl+点击命中链**：画布 pointerdown（capture）已按坐标命中白板卡片开文档（`boardCardAt`），扩展一个「命中 embeddable 元素」分支即可。
- **openTab 分屏**：siyuan.d.ts 确认 `openTab({ position: "right" })` 官方支持 → 「白板页签 + 文档页签并排」的双页阅读**一步可达**，不用碰内部 layout API。
- **斜杠菜单**：`protyleSlash` 已注册一项（「白板」→ 新建）；再推一项零风险。
- **白板选择器**：`pickBoardRef()` 已存在（「插入白板卡片」画布动作在用），选库内任意 .svg 返回 `assets/excali/x.svg`。
- **图片块右键**：`registerBlockIconMenu` 已对含 `assets/*.svg` 的块挂「用 Excali 白板打开」；`![](assets/excali/x.svg)` 的插入写法与建档流程 `appendImageBlock` 同构。

## 二、实现方案

### 功能 A：拖文档/块进画布 → 交互框 + 点击双页阅读

**A1 拖拽识别与建框**（改动：StudioApp.tsx + embeddable.ts）

1. `.exs-root` 容器挂 `dragover`/`drop`（capture）：
   - dragover：`e.dataTransfer.types` 含 `application/siyuan-documents` / `-file` / `-gutter` 前缀 → `preventDefault()` + 画布顶部出现提示条「松开，嵌入思源块」（复用菜单实底样式 token）。
   - drop：解析块 ID——优先级 `siyuan-documents`（JSON.ids）→ `siyuan-file`（逗号拆分后按块 ID 形状 `[0-9]{14}-[0-9a-zA-Z]{7}` 过滤，path 形态=笔记本则忽略并 toast）→ `siyuan-gutter*`（MIME 按零宽空格切第三段）。
2. `clientToScene`（已有）换算落点 → 复用 `makeEmbeddableElement + embedPageLink`；多块 ID 拖入按 2 列网格自动排布；插入后选中并 toast「已嵌入 N 个思源块」。
3. MIME 解析写成 embeddable.ts 里的**纯函数**（`siYuanDropIds(dataTransfer)`），配单测（含脏数据/非文档拖拽/多选）。

**A2 点击跳转与双页**（改动：src-embed/siyuan/index.html + StudioApp.tsx + index.ts）

1. 嵌入页「在思源中打开」按钮改为 `postMessage({type:"exs-open-block", blockId}, location.origin)`（去掉 `_top` 跳转）；StudioApp 挂 `message` 监听 → `host.openDocLink`。
2. 宿主 `openBoardDocLink` 增加文档分支：`openTab({ app, doc:{ id }, position:"right" })` → 文档在右侧新分屏打开，白板留在原处 = **双页阅读**。（移动端 openTab 为空实现 → 回退 `openDocumentById` 常规打开。）
3. ⌘/Ctrl+点击嵌入框直接跳：现有 pointerdown 命中链在 `boardCardAt` 未命中后追加 embeddable 命中（元素带 `/plugins/…/embed/` link）→ 同一 openDocLink 通道。免按键入口 = ①；习惯键位 = ③；两全。
4. 框的可视暗示：embeddable 元素默认 `strokeColor: transparent` 不改（贴参照插件视觉），但在选中态由 vendor 自带边框提示；toast 文案说明「⌘点击或右上按钮打开文档」。

**A3 边界**：移动端无拖拽（功能天然桌面限定，不需适配）；拖 PDF/图片资源进画布走 vendor 既有图片路径不受影响；同一文档重复拖入允许（用户自管）。

### 功能 B：斜杠「插入白板…」→ 文档内交互框 + 跳转

**B1 插入**（改动：index.ts）

1. `protyleSlash` 第二项：`id:"excaliStudioInsert"`，`filter:["插入白板","白板卡","excali"]`，图标沿用 STUDIO_ICON；html 照抄 `slashItemHtml` 结构（现有约定）。
2. 回调：`pickBoardRef()` 选一张库内白板 → `protyle.insert("![](assets/excali/x.svg)")` —— 与参照插件同构，但**不建占位文件**（我们的白板本来就是真实文件，所见即所得）；取消则不动正文。
3. 移动端斜杠菜单同样可用（protyleSlash 是思源原生能力），picker 已有移动形态。

**B2 交互框的三条跳转入口**（改动：index.ts + 新文件 hover 注入模块）

对齐参照插件的入口布局，全部落到已有的 `openStudioTab(path)`：

1. **图片右键菜单（思源原生事件）**：`eventBus.on("open-menu-image")`，目标是 `assets/excali/*.svg` 时加「用 Excali 白板打开」。这是最稳的入口（无 DOM 注入）。
2. **块头悬停 ↗ 按钮（DOM 注入）**：新文件 `board-block-decorate.ts`，`switch-protyle`/`click-editorcontent` 时扫描当前编辑器 `img[src*="assets/excali/"]`，往其块 `.protyle-action` 注入 ↗ 图标（模式抄自家 `library-menu-inject.ts` 的「注入-断连-重扫」纪律；参照插件同款手法，思源 DOM 这层长期稳定）。
3. **块徽标（可选）**：`.protyle-attr` 贴「Excali」label（参照插件同款），让交互框可辨识；做成设置开关，默认开。

**B3 与「复制此白板引用」的关系**：保留 ☰ 菜单项（刚重做成「一键建档+行内引用」，语义清晰）；斜杠插入是**文档侧**的正向入口，两条路各管一头，不冲突。若你更想砍掉 ☰ 项只留斜杠，一行删除即可（契约测试同步）。

## 三、工作量、顺序与风险

| 批次 | 内容 | 涉及文件 | 量级 |
|---|---|---|---|
| 1 | A1 拖拽识别+建框（含 MIME 纯函数+单测） | embeddable.ts / StudioApp.tsx | 中 |
| 2 | A2 跳转双页（postMessage + openTab position） | src-embed/siyuan/index.html / StudioApp.tsx / index.ts | 小 |
| 3 | B1 斜杠插入 | index.ts | 小 |
| 4 | B2 右键菜单 + 悬停按钮 + 徽标 | index.ts / 新 board-block-decorate.ts | 中 |
| 5 | 契约测试 + release-checklist 两条验收 + CHANGELOG | test/ docs/ | 小 |

**风险与对策**
- 拖拽 MIME 是思源内部协议，无兼容承诺 → 解析全防御式，types 缺失即静默放弃；用契约测试把三种 MIME 形态钉住，思源升级若变，测试先红。
- gutter 的动态 MIME 含零宽空格，肉眼难查 → 纯函数 + 明确单测。
- 悬停按钮依赖 protyle DOM 结构 → 与参照插件、自家 library-menu-inject 同级风险；注入器做成可整体失败（找不到就不注入，不抛错）。
- openTab `position:"right"` 为官方 API（siyuan.d.ts:501），低风险；移动端空实现已由现有 isMobileFrontend 分支兜住。

**验收清单预告**（进 release-checklist）：拖单文档/多文档/笔记本（应忽略）/正文块四态；嵌入框点 ↗ 与 ⌘点击均右侧分屏打开原文档；斜杠插入后文档里见白板预览，悬停 ↗ 与右键能跳；移动端斜杠可用、拖拽不受影响。
