## 一、类型信息从哪来（不用动 MIME 解析）

**SQL 一次带全。** 现有 `fetchBlockTitles` 的查询只取 `id, content`；`blocks` 表本来就有
`type` / `subtype` 两列，把查询扩成 `select id, content, type, subtype from blocks where id in (...)`
即可，调用方本来就是异步等这批数据，**零额外请求、零时序问题**。

思源 `blocks.type` 取值（对照官方搜索过滤菜单实测）：

| type | subtype | 含义 | 常见度 |
|---|---|---|---|
| `d` | — | 文档 | ★ 必做 |
| `p` | — | 段落 | ★ 必做 |
| `h` | h1~h6 | 标题 | ★ 必做 |
| `l` | o / u / t | 列表（有序/无序/任务） | ★ 必做 |
| `i` | o / u / t | 列表项 | ★ 必做 |
| `c` | — | 代码 | ★ 必做 |
| `m` | — | 公式 | ★ |
| `t` | — | 表格 | ★ |
| `b` | — | 引述 | ★ |
| `s` | — | 超级块 | ★ |
| `av` | — | 数据库 | ★ |
| `query_embed` | — | 嵌入块（SQL） | ★ |
| `html` | — | HTML 块 | ★ |

> 备用信息源：gutter 拖拽的动态 MIME 名本身就带 `NodeXxx`+subtype（思源
> `isSupportedDrop` 亲测 `siyuan-gutter + NodeParagraph/NodeListItem/NodeAttributeView…` 结构）。
> 但它是无兼容承诺的内部协议且覆盖不到文档拖拽；**SQL 为主即可，MIME 解析留作可选降级，本期不做。**

## 三、画布上怎么画（方案对比）

### 方案 A（推荐）：独立小图标元素 + 文字成组

Obsidian 的 📍 本质是「文字前缀 emoji」，受 emoji 表情限制、和 Lucide 笔形不搭。
我们直接插一个微型 image 元素：

1. **图标 → data URL**：`<svg xmlns viewBox="0 0 24 24" fill="none" stroke="{accent色}" …>{path}</svg>`
   编码成 `data:image/svg+xml`（单枚 300~500 字节，可忽略）；
2. **注册 + 插入**：`api.addFiles([{ id, dataURL, mimeType: "image/svg+xml" }])` +
   skeleton `{ type: "image", fileId, x, y, width, height }`——与现有
   `image-import.ts`（解码 → addFiles → convertToExcalidrawElements）完全同一条
   已验证链路，`transform.d.ts` 确认 image skeleton 支持 `fileId` + Partial；
3. **成组**：icon 与 text 元素设同一个 `groupIds`（vendor restore 认 groupIds，无需
   额外 API），图标约 1.1×字号、垂直居中、间距 ~6 场景单位；
4. **链接**：`link: siyuan:block/<id>` 同时设在两个元素上——vendor 原生 `onLinkOpen`
   对任何带 link 的元素都触发，StudioApp 的 `siyuan:` 拦截照常生效。

- 优点：真思源图标、矢量清晰、可整体选中拖动、和 Obsidian 的观感对齐；
- 代价：比纯文字多一个元素/每次拖拽 + 一个 file 记录。**需验证**：`scene-codec`
  对 SVG mime 的 files 往返（现有图片外置逻辑针对位图，SVG data URL 应走内联路径，
  实施第一步先验证这个，不行就退位图）。

### 方案 B（保底）：文字前缀字符

`blockLinkTextSkeleton` 的 text 前面拼一个区分字符（如 Obsidian 的 📍 / 自绘 Unicode）。
零链路改动，但表达力差、与手绘风不搭——只作 A 验证失败时的退路，不展开。

## 四、字体跟随

- **读法**：`api.getAppState().currentItemFontFamily`（vendor `appState.d.ts:28`，
  数字枚举）。插件字体补丁（`scripts/excalidraw-fonts-patch.mjs`）把中文六字体注册为
  101~106、小赖 100、原生 Virgil=1 / Normal=2 / Code=3——选择器里选什么，这个值就是什么；
- **写法**：skeleton 的 `fontFamily` 是**字符串**形态（现硬编码 `"1"`），把
  `String(currentItemFontFamily)` 传进去即可命中补丁后的枚举。实施时先手工验证一枚
  中文 id（如 102）能被 `convertToExcalidrawElements` 正确落到元素的 fontId；
- **改动点**：`blockLinkTextSkeleton` 加可选参 `fontFamily`（默认回落 "1"），
  StudioApp 传入；顺手可加 `fontSize` 跟随 `currentItemFontSize`（可选，默认维持 20）。

## 六、边界情况

1. **数据库行 / 视图页签拖入**：id 形状合法但不在 `blocks` 表 → SQL 查不到 → 回退
   「通用块图标 + 块号」文案（与现状一致，只是多了个通用图标）；
2. **SQL 失败 / 索引延迟**：同上回退，不阻塞插入（现状语义）；
3. **明暗主题**：图标 stroke 色用与文字同源的 `--exs-accent` 两态值，无额外两套资产；
4. **混合多选**（`siyuan-file` 含笔记本 path）：现有 ID 形状过滤已挡，无需处理；
5. **文档树上拖笔记本**：笔记本无 id，现有过滤已挡；
6. **旧白板兼容**：新元素就是普通 text+image+groupIds+link，旧链路（保存/解码/跳转）天然认；
7. **未来扩展**（本期不做）：思源还有 `siyuan-block-ref`（书签/标签面板拖块）、
   `siyuan-tab`（页签拖拽）两种 MIME，可后续接进同一条链路；分隔线/数据库行这类
   思源自家都拦的类型不做。
