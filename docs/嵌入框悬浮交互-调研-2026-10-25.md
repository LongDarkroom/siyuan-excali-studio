# 画布嵌入框悬浮按钮不稳定 & 交互卡顿：调研报告（2026-10-25）

> 现象（用户）：嵌入思源块的交互不稳定——右上角悬浮按钮「最开始两个，点击后变三个」，交互不流畅。本报告只调研，未改码。

---

## 一、现象解剖：悬浮在嵌入框附近的 UI 其实有 **四层来源**

逐层翻 vendor（engine.js）与自家代码后，悬浮在嵌入框右上角的按钮来自四套独立机制：

| # | 来源 | 形态 | 出现条件 |
|---|------|------|---------|
| 1 | **vendor 超链弹窗** `excalidraw-hyperlinkContainer`（`showHyperlinkPopup` 状态机） | 深色圆角药丸：链接文本 + [打开 ↗] [⋯编辑]（info 态 2 键）；点 ⋯ 进 editor 态变 **3 键**（+ 移除 ✕，还有输入框） | 元素被**选中** 且（有 `link` **或** 是 embeddable——后者无条件命中）。我们拖入的文字链接和嵌入框都中 |
| 2 | **vendor 交互提示** `excalidraw__embeddable-hint`（「点击以交互」药丸） | 居中大药丸 | embeddable 处于未激活态（hover/静止都渲染，激活后消失） |
| 3 | **vendor 画布悬浮按钮簇** `excalidraw-canvas-buttons` | 单选元素上方的 ToolIcon 小圆钮（如 AI magic 按钮、全屏） | 单选 + 无弹层互斥时；截图 2 里第三个「🖼 复制为 PNG」即这类（copyAsPng 文案在 vendor 语言包，SiYuan 桌面 bundle 无此串——实锤来自 vendor） |
| 4 | **我们嵌入页自己的 hover 按钮**（src-embed/siyuan/index.html 的 `#buttons`：刷新 / 在思源中打开） | iframe 内右上两个文字小钮 | iframe 内 `body:hover` |

**「2 → 3 个按钮」的直接解释**：第 1 层的 info 态（2 键：打开 + ⋯）在点击后切到 editor 态（3 键：+ 移除），或与第 3 层按钮簇叠显。四层各自有独立的挂载/卸载条件（hover、选中数=1、激活态、弹层互斥），叠加在同一角落 → 观感「随机变化」。

## 二、「不流畅」的机制

1. **弹窗按 pointermove 逐帧重算位置**：`showHyperlinkPopup` 存续期间每次鼠标移动都走 `CLA()` 定位计算 + setState → React 重渲染药丸（位置、内容双抖动）。
2. **pointer-events 三态翻转**：vendor 用 `--ui-pointerEvents` 在「画布可拖」/「iframe 可交互」间切换；嵌入框激活后指针事件交给 iframe，移出再翻转——鼠标路径稍有回摆就在两套事件体系间来回弹。
3. **hover/active 状态机三态**（null → hover → active）：点击嵌入框中心 → 100ms 延时切 active + 选中；移出 → hover 撤销。每次切换都伴随提示药丸（第 2 层）挂卸 + 选中环重绘。
4. **第 4 层的 CSS hover**（我们 iframe 内）与 vendor 覆盖层互相争抢鼠标，body:hover 瞬间亮灭。

## 三、稳定化方案（供选择，推荐 A）

**方案 A · 单一控制面：把「打开/刷新」收敛进自渲染层，vendor 的三层 UI 对插件嵌入全部屏蔽（推荐）**

- `renderPluginEmbeddable` 已是自渲染 React 层——在其中**内置一条稳定的顶部工具条**（元素 hover 时淡入）：`↗ 打开文档` + `⟳ 刷新`，一次渲染常驻、无状态机、无 pointermove 重算（这才是用户唯一需要的两个动作；vendor 弹窗的「编辑链接/移除链接/复制PNG」对思源块毫无意义）。
- CSS 屏蔽 vendor 三层：`.excalidraw-hyperlinkContainer`、`.excalidraw__embeddable-hint`、`.excalidraw-canvas-buttons` 中针对嵌入框的部分——**难点**：hyperlinkContainer 也服务普通文字链接（我们拖入的标题文字要靠它「打开」吗？不需要——单击文字本身 vendor 就触发 onLinkOpen 打开；弹窗是冗余的）。可全局隐藏 hyperlinkContainer，但 `⋯` 的「编辑链接」能力对用户手画连线/文字也一起没了——建议先试全局隐藏，反馈不好再按元素类型细化。
- 我们的 ⌘点击/单击开文档链路不动。
- 改动面：renderPluginEmbeddable 加工具条 + embeddable.ts 加开关常量 + index.css 三条屏蔽规则 + 嵌入页 `#buttons` 移除（职责并入工具条，iframe 内不再有浮层）。量级：小。

**方案 B · 保守修：只治抖动，保留 vendor 交互**

- CSS 给 `.excalidraw-hyperlinkContainer` 加 `transition: opacity 120ms` + `pointer-events` 稳定化，隐藏 editor 态的移除键（信息态足够）；hint 药丸加淡入。抖动会明显减轻，但四层 UI 依旧并存，「2↔3 键」观感只是变缓和。量级：极小，治标。

**方案 C · A + 拖入文字也接管**：连文字链接的 vendor 弹窗一并隐藏，文字的打开完全依赖单击（行为与 Obsidian 一致：点文字即跳）。最简观感，但丢失「右键/⌘K 编辑链接」能力——本插件场景用不到，风险低。

## 四、建议

A（C 作为可选项并入）。理由：我们的嵌入框是「查看 + 跳转」语义，不需要 vendor 为通用网页嵌入设计的交互栈；自渲染层做一条稳定工具条是唯一能让按钮**恒定两个**的办法。确认后我按 A 实施（嵌入页删按钮、工具条统一、三条 CSS 屏蔽、契约测试同步）。
