> 起因：用户反馈「插件很多问题」——菜单背景不透明、菜单里 GitHub/关注 X 不需要、复制白板引用用不了、嵌入思源块用不了。本报告覆盖这四项的根因定位 + 全库断线普查（回调接线、i18n、TODO、竖条动作、kernel MCP、embed 页、测试跳过项、README 漂移）。

## 一、点名的四个问题：根因全部定位

### 1. ☰ 菜单背景不透明 —— 设计取舍，改起来是一行

- 位置：`src/index.css`（第二十六轮「Apple UI」批次）。
- 机制：菜单/右键菜单背景用的是 `--exs-menu-bg: rgba(250,250,252,0.86)`（浅色）/ `rgba(39,39,43,0.86)`（深色）+ `backdrop-filter: blur(20px) saturate(180%)`，是刻意的毛玻璃风格，不是渲染 bug。
- 实底色 token 已经存在（`--exs-menu-solid: #fbfbfd` / `#2c2c2e`），把 `@supports (backdrop-filter…)` 那段规则里的 `background: var(--exs-menu-bg)` 换成实底（或删掉该 @supports 覆盖块回落 vendor 实底）即可。
- 建议：直接切实底（用户明确不喜欢透出画布），保留阴影与圆角。

### 2. 菜单里的 GitHub / 关注我们(X) / Discord —— 代码里显式渲染的上游组件

- 位置：`src/studio/StudioMenu.tsx:118-121`：
  ```tsx
  <MainMenu.Separator />
  <MainMenu.Group title={t("Excalidraw 链接")}>
    <MainMenu.DefaultItems.Socials />
  </MainMenu.Group>
  ```
- `DefaultItems.Socials` 就是 Excalidraw 官方的社交链接组（GitHub / Follow us on X / Our Discord）。自建白板插件确实不该带。删掉这 4 行（连同前后 Separator 之一）即净。
- **顺带发现（同一张截图可见）：「帮助」出现了两次** —— `StudioMenu.tsx:112-114` 是插件自建「帮助」（快捷键速查，宿主 Dialog），`:116` 又渲染了上游 `MainMenu.DefaultItems.Help`（打开 excalidraw.com 文档）。二者文案都是「帮助」→ 重复项。删上游那个，保留自建的。
- 另一个观察项：`:123` 的 `DefaultItems.ToggleTheme`（切换明暗）与插件「画布跟随思源主题」的机制并存，用户手动切了菜单主题后画布与思源主题脱钩，可能造成困惑——建议一并去掉，主题统一跟随思源。

### 3. 复制白板引用「用不了」—— 两层真实症结（不是崩溃）

代码链路完整（`StudioMenu` → `tab.tsx:302` → `index.ts:2500 copyBoardRefFor` → `copyText`，剪贴板还有 execCommand 双兜底）。症结在语义：

- **症结 A：前置条件陷阱**。引用需要文档块的 `docId`，只有「建档」过的白板才有。未建档时点击只弹 toast「还没建档，复制不了引用：在白板行右键『建档』」——而「建档」入口藏在 **dock 白板库列表的右键菜单**里，菜单项本身不引导。绝大多数用户到这里就判定功能坏了。
- **症结 B：复制物是 kramdown 文本，粘贴不落地**。`embedRef()` 生成 `![[块ID]]`（`board-lib.ts:168`）。思源正文粘贴纯文本不会把 `![[…]]` 自动转成块嵌入块——复制成功、粘贴出来是一串字面文本，看起来还是「没用」。真正把图插进文档的通道是「保存到文档」（插图片块），与本菜单项语义重叠。
- **修复建议**：
  - 未建档时菜单项行为改为「建档并复制引用」一步完成（建档逻辑已有：`index.ts:2186 createDocFor`）；
  - 默认复制改 `((块ID "标题"))` 行内引用（粘贴后是可点的反链引用），嵌入引用放次级；或在 toast 里写清「粘贴到正文后再按回车转换」之类的正确用法；
  - 长期看此项与「保存到文档」职责重叠，可考虑合并成一个「引用与分享」子菜单。

### 4. 嵌入思源块「用不了」—— 根因实锤：vendor 沙箱白名单（本报告最重要发现）

- 现象链：菜单点击正常 → 输入框弹出正常 → 粘贴块链接 → 画布上出现嵌入框 → **框里永远显示「读取块失败：Auth failed [session]」或空白** → 判定用不了。
- 根因（在 `engine.js` 产物里逐段核对）：
  1. Excalidraw 0.18.1 对 embeddable 元素渲染的 `<iframe>` 强制加 `sandbox`，其中 `allow-same-origin` **只对九个域名白名单开放**：
     `youtube.com / youtu.be / vimeo.com / player.vimeo.com / figma.com / twitter.com / x.com / *.simplepdf.eu / stackblitz.com / reddit.com`（产物内 `ydA` 集合）。
  2. 我们的嵌入渲染页链接是 `/plugins/siyuan-excali-studio/embed/siyuan/index.html?blockId=…`，属于 generic 链接 → sandbox 为 `" allow-scripts allow-forms allow-popups …"` **不含 `allow-same-origin`**。
  3. 无 `allow-same-origin` 的 iframe 是 opaque origin：页面里 `fetch("/api/block/getBlockDOM")` 带不上内核会话 cookie，内核一律回 `{"code":-1,"msg":"Auth failed [session]"}`（已用运行中的内核实测复现：不带会话的请求必 401）。
  4. 隔壁 siyuan-embed-excalidraw 的 embed 页同样是裸 fetch，但它捆的是**加固之前的老版 vendor**（iframe 没有 sandbox），所以它能工作——不是我们 fetch 写错了，是 vendor 升级带来的行为变化。
- **修复方向（明确可行）**：vendor 的 `renderEmbeddable` prop（自定义嵌入渲染，产物里已消费该 prop）——对 `/plugins/…/embed/` 前缀的链接**自己渲染 iframe**（同源可信页，sandbox 显式给 `allow-scripts allow-same-origin allow-popups`，或不加 sandbox），其余链接回落 vendor 默认渲染。改动集中在 StudioApp.tsx 一个渲染函数 + 对应测试。
- 附带：嵌入页本身（`src-embed/siyuan/index.html`）逻辑健康（端点、样式、错误态齐全，与产物逐字节一致）。
